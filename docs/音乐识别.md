一、总体实现方案
========

针对你的普通 Web 应用，我推荐采用：

getDisplayMedia + Web Audio API + AudioWorklet + libsonare StreamAnalyzer

整个分析过程都在用户浏览器本地运行，不需要把系统声音上传到服务器。

电脑系统声音

音乐播放器、浏览器、游戏、其他应用

getDisplayMedia()

用户选择整个屏幕，并授权共享系统音频

Web Audio API / AudioWorklet

获取 PCM、立体声转单声道、分块传递

libsonare StreamAnalyzer

实时提取 Mel、Chroma、Onset、RMS、频谱特征

持续更新 BPM、调性、和弦估计

音乐判断

Music / Non-music / Unknown

BPM 检测

Tempo + Confidence

这里有一个关键区别：libsonare 的 `StreamAnalyzer` 是真正支持逐块输入的实时分析器，`stats()` 可以读取逐渐收敛的 BPM、调性和和弦估计。它不是现成的歌曲分类器。

libsonare+2

需要先了解的浏览器限制
-----------

浏览器不能直接、静默地获取整台电脑的声音。需要用户主动授权屏幕共享。

在 Chrome 中，推荐让用户选择「整个屏幕」，并启用「共享系统音频」。`systemAudio: "include"` 只是向浏览器提出提示，并不能保证一定拿到音轨；实际必须检查 `getAudioTracks()`。浏览器和操作系统的能力也会影响结果。

MDN+2

此外，网页必须通过 HTTPS 运行（本地开发时 localhost 通常可以）。

二、安装与 Worklet 配置
================

这里有一个好消息：libsonare 已经提供了 `SonareStreamAnalyzerNode`，能够直接把 Web Audio 音频节点连接到实时分析器。

三、实时系统声音检测核心代码
==============

创建：

`src/audio/SystemAudioMusicDetector.ts`

下面这套实现包含：

-   获取系统声音授权。

-   检查是否成功取得音轨。

-   初始化 libsonare WASM。

-   建立 AudioWorklet 分析链路。

-   持续读取音频特征。

-   获取 BPM、调性、和弦置信度。

-   初步判断当前声音是否具有音乐特征。

-   支持停止采集和释放资源。

```

import { init } from '@libraz/libsonare';
import {
  SonareStreamAnalyzerNode
} from '@libraz/libsonare/worklet';

export type MusicState =
  | 'silence'
  | 'likely-music'
  | 'uncertain';

export interface MusicSnapshot {
  state: MusicState;

  // BPM
  bpm: number | null;
  bpmConfidence: number;

  // 音乐特征
  key: string | null;
  keyConfidence: number;
  chord: string;
  chordConfidence: number;

  // 音量
  audioLevelDb: number;
}

export class SystemAudioMusicDetector {
  private stream?: MediaStream;
  private audioContext?: AudioContext;

  private source?: MediaStreamAudioSourceNode;

  private analyzer?: Awaited<
    ReturnType<typeof SonareStreamAnalyzerNode.create>
  >;

  private stopFrames?: () => void;
  private stopStats?: () => void;

  private recentRms: number[] = [];

  private estimate = {
    bpm: 0,
    bpmConfidence: 0,

    keyName: null as string | null,
    keyConfidence: 0,

    chordName: 'N.C.',
    chordConfidence: 0
  };

  constructor(
    private readonly onUpdate:
      (result: MusicSnapshot) => void,

    private readonly onStatus:
      (status: string) => void = () => {}
  ) {}

  /**
   * 开始捕获系统声音。
   *
   * 必须从用户点击按钮的事件中调用。
   */
  async start(): Promise<void> {
    if (this.audioContext) {
      throw new Error('检测器已经启动');
    }

    if (!navigator.mediaDevices?.getDisplayMedia) {
      throw new Error('当前浏览器不支持屏幕音频捕获');
    }

    this.onStatus('等待系统声音授权...');

    // 必须在用户点击事件中立即调用，不能先等待其他异步操作。
    const capturePromise =
      navigator.mediaDevices.getDisplayMedia({
        video: true,
        audio: true,
        systemAudio: 'include',
        selfBrowserSurface: 'exclude'
      } as unknown as DisplayMediaStreamOptions);

    const audioContext = new AudioContext({
      latencyHint: 'interactive'
    });

    this.audioContext = audioContext;

    // 同样在用户手势期间启动 AudioContext。
    const resumePromise = audioContext.resume();

    try {
      // 等待用户完成屏幕共享授权。
      const stream = await capturePromise;
      this.stream = stream;

      const audioTracks = stream.getAudioTracks();

      if (audioTracks.length === 0) {
        throw new Error(
          '没有获取到系统音频。请重新共享整个屏幕，' +
          '并开启共享系统音频选项。'
        );
      }

      this.onStatus('正在初始化 libsonare...');

      // 初始化 WASM。
      await init();
      await resumePromise;

      // 注册并加载 libsonare AudioWorklet。
      await audioContext.audioWorklet.addModule(
        '/sonare-analyzer-worklet.js'
      );

      // 初始化实时分析器。
      this.analyzer = await SonareStreamAnalyzerNode.create(
        audioContext,
        {
          config: {
            nFft: 2048,
            hopLength: 512,
            nMels: 64,

            computeMel: true,
            computeChroma: true,
            computeOnset: true,
            computeSpectral: true,

            // 降低 UI 特征帧的更新频率。
            emitEveryNFrames: 4,

            // 限制未读取的特征帧数量。
            maxPendingFrames: 256,

            // BPM 和调性估计更新间隔。
            bpmUpdateIntervalSec: 5,
            keyUpdateIntervalSec: 5
          }
        }
      );

      // 只使用系统音频轨道。
      const audioStream = new MediaStream(audioTracks);

      this.source =
        audioContext.createMediaStreamSource(audioStream);

      // 接收特征帧。
      this.stopFrames = this.analyzer.onFrames(
        (frames) => {
          this.handleFrames(frames);
        }
      );

      // 接收音乐分析结果。
      this.stopStats = this.analyzer.onStats(
        (stats) => {
          const e = stats.estimate;

          this.estimate = {
            bpm: e.bpm,
            bpmConfidence: e.bpmConfidence,

            keyName: e.keyName,
            keyConfidence: e.keyConfidence,

            chordName: e.chordName,
            chordConfidence: e.chordConfidence
          };

          this.publish();
        }
      );

      // 连接音频输入和分析器。
      // SonareStreamAnalyzerNode 没有音频输出，
      // 因此不会将采集到的声音再次播放出来。
      this.source.connect(this.analyzer.node);

      // 用户在浏览器共享栏点击停止时自动清理。
      const handleEnded = () => {
        void this.stop();
      };

      stream.getTracks().forEach((track) => {
        track.addEventListener('ended', handleEnded, {
          once: true
        });
      });

      this.onStatus('正在检测系统声音...');
      this.publish();

    } catch (error) {
      await this.stop();
      throw error;
    }
  }

  /**
   * 接收 libsonare 提供的实时特征帧。
   */
  private handleFrames(frames: {
    nFrames: number;
    rmsEnergy: Float32Array;
  }): void {

    for (let i = 0; i < frames.nFrames; i++) {
      this.recentRms.push(
        frames.rmsEnergy[i] ?? 0
      );
    }

    // 保留最近约数秒的音量特征。
    if (this.recentRms.length > 180) {
      this.recentRms.splice(
        0,
        this.recentRms.length - 180
      );
    }

    this.publish();
  }

  /**
   * 发布检测结果。
   */
  private publish(): void {
    const values = this.recentRms;

    const avgRms = values.length
      ? values.reduce((sum, value) => sum + value, 0)
        / values.length
      : 0;

    const audioLevelDb =
      20 * Math.log10(Math.max(avgRms, 1e-8));

    const e = this.estimate;

    // 初步声音门限。
    // 实际使用时应根据不同系统的采集音量调整。
    const hasAudio =
      values.length >= 5 &&
      audioLevelDb > -55;

    // 节奏特征。
    const hasStableTempo =
      e.bpm > 0 &&
      e.bpmConfidence >= 0.35;

    // 调性或和弦特征。
    const hasHarmonicStructure =
      e.keyConfidence >= 0.20 ||
      e.chordConfidence >= 0.20;

    // 仅作为初步音乐特征判断，不是正式音乐分类模型。
    const likelyMusic =
      hasAudio &&
      hasStableTempo &&
      (
        hasHarmonicStructure ||
        e.bpmConfidence >= 0.65
      );

    const state: MusicState =
      !hasAudio
        ? 'silence'
        : likelyMusic
          ? 'likely-music'
          : 'uncertain';

    this.onUpdate({
      state,

      bpm: e.bpm > 0 ? e.bpm : null,
      bpmConfidence: e.bpmConfidence,

      key: e.keyName,
      keyConfidence: e.keyConfidence,

      chord: e.chordName,
      chordConfidence: e.chordConfidence,

      audioLevelDb
    });
  }

  /**
   * 停止分析并释放浏览器资源。
   */
  async stop(): Promise<void> {
    this.stopFrames?.();
    this.stopStats?.();

    this.stopFrames = undefined;
    this.stopStats = undefined;

    this.source?.disconnect();
    this.source = undefined;

    this.analyzer?.destroy();
    this.analyzer = undefined;

    this.stream?.getTracks().forEach((track) => {
      track.stop();
    });

    this.stream = undefined;

    const context = this.audioContext;
    this.audioContext = undefined;

    if (context && context.state !== 'closed') {
      await context.close();
    }

    this.recentRms = [];

    this.estimate = {
      bpm: 0,
      bpmConfidence: 0,
      keyName: null,
      keyConfidence: 0,
      chordName: 'N.C.',
      chordConfidence: 0
    };

    this.onStatus('声音检测已停止');
  }
}

```

这段代码使用的是官方的 `SonareStreamAnalyzerNode` 和 `StreamAnalyzer` 接口，而不是假设存在一个 `isMusic()` 函数。官方接口支持 `onFrames()` 和 `onStats()` 两种实时回调。

四、React 页面调用示例
==============

可以在 React 页面添加两个按钮，一个负责开始监听，另一个负责停止监听。

```
import { useRef, useState } from 'react';

import {
  SystemAudioMusicDetector,
  MusicSnapshot
} from './audio/SystemAudioMusicDetector';

export function MusicMonitor() {
  const detectorRef =
    useRef<SystemAudioMusicDetector | null>(null);

  const [status, setStatus] = useState('尚未启动');
  const [result, setResult] =
    useState<MusicSnapshot | null>(null);

  const start = async () => {
    const detector = new SystemAudioMusicDetector(
      setResult,
      setStatus
    );

    detectorRef.current = detector;

    try {
      await detector.start();
    } catch (error) {
      setStatus(
        error instanceof Error
          ? error.message
          : '启动失败'
      );
    }
  };

  const stop = async () => {
    await detectorRef.current?.stop();
    detectorRef.current = null;
    setResult(null);
  };

  return (
    <div>
      <h2>实时音乐检测</h2>

      <p>状态：{status}</p>

      <button onClick={start}>
        开始监听
      </button>

      <button onClick={stop}>
        停止监听
      </button>

      {result && (
        <section>
          <h3>
            {result.state === 'silence'
              ? '没有声音'
              : result.state === 'likely-music'
                ? '检测到疑似音乐'
                : '正在分析声音特征'}
          </h3>

          <h1>
            {result.bpm !== null
              ? `${result.bpm.toFixed(1)} BPM`
              : '-- BPM'}
          </h1>

          <p>
            BPM 置信度：
            {(result.bpmConfidence * 100).toFixed(1)}%
          </p>

          <p>
            调性：{result.key ?? '--'}
          </p>

          <p>
            当前和弦：{result.chord}
          </p>

          <p>
            音量：{result.audioLevelDb.toFixed(1)} dB
          </p>
        </section>
      )}
    </div>
  );
}
```

这里的 `start()` 必须直接从用户点击事件调用，不能先通过其他异步流程延迟调用屏幕共享 API。

六、关于是否为歌曲的识别，我建议再完善一层
=====================

上面代码采用的是规则判断，不能将它视为准确的歌曲分类模型。

例如：

| 输入声音 | 可能出现的问题 |
| --- |  --- |
| 流行歌曲 | 通常容易检测到节奏和和弦 |
| 纯鼓点音乐 | 可能有 BPM，但没有明显调性 |
| 人说话 | 可能有周期性声音，但不一定是音乐 |
| 游戏音效 | 可能有音乐特征，但并非歌曲 |
| 环境噪音 | 通常没有稳定节奏，但不能保证 |

我建议最终将识别结果设计成三个等级：

Music

确认具有音乐特征

有稳定节奏，并且有一定旋律、和弦或其他音乐特征。

Unknown

无法确定

有声音，但是音乐特征不足，或者 BPM 结果尚不稳定。

Silence

没有有效声音

当前音量低于设定阈值。

如果将来需要高准确率地排除语音、游戏音效和环境噪音，可以在 libsonare 后面增加专门的音频分类模型。

libsonare 已经可以提供 Mel、Chroma、Onset 等特征，但仓库本身不包含深度学习分类模型。

七、BPM 检测需要注意的问题
===============

还有两个实际问题需要考虑。

1\. 不要过早确定 BPM

libsonare 的实时估计会随着音频不断更新。最初几秒钟的 BPM 可能不稳定，建议：

-   0～2 秒：收集音频特征。

-   2～5 秒：显示初步估计。

-   5～10 秒：逐步提高可信度。

-   后续：持续更新。

我们在代码中将 `bpmUpdateIntervalSec` 设置为 5 秒，以便更快更新，但初始估计仍然需要视为暂定结果。

libsonare+1

2\. BPM 可能出现半拍或双倍拍

例如一首实际 120 BPM 的歌曲，算法有可能识别为 60 BPM 或其他相关节奏。这是节奏周期检测常见的歧义，不一定是算法错误。

九、器灵桌面版的实际落地（2026-11-08）
================

上面的讨论针对浏览器（`getDisplayMedia` + `libsonare`）。器灵桌面版已经有原生采集链路，落地时没有直接照搬浏览器方案：

| 环节 | 讨论方案 | 器灵桌面版 |
| --- | --- | --- |
| 系统声音采集 | `getDisplayMedia` + Web Audio | Windows WASAPI 回环（`src-tauri/src/music.rs`），不需要分享屏幕 |
| 实时特征 | libsonare `StreamAnalyzer` | Rust 自带 FFT：24 个对数频带（40 Hz–8 kHz）起音包络、低频占比、响度占空比 |
| 音乐/非音乐 | 规则判断 + 以后加分类模型 | 规则判断（已实现），暂不引入模型 |
| BPM | libsonare tempo + 置信度 | 起音包络自相关 + 梳状滤波 + 速度先验 + 节拍网格相位 |

### 1. 怎么区分音乐和人声

只看音量会把所有声音都当成音乐。现在的判定用四类证据，并带滞回：

1. **起音规律**：全带宽频谱通量（不是只看低频鼓点）形成 onset strength envelope（OSE）；音乐通常有稳定周期，语音的音节间隔不规则。
2. **节拍网格质量**：对候选速度铺拍点，检查覆盖率、每拍是否都有起音（occupancy）、各拍强弱是否规整（regularity）。语音即使语速稳定，也很难同时满足这三点。
3. **低频占比**：音乐（尤其流行、电子）通常有持续低频；纯人声很少。这个特征只占小权重，独奏钢琴/清唱不靠它。
4. **响度占空比**：音乐是持续的；单次提示音、游戏音效之间大量静音，会被占空比门限挡掉。
5. **音色通道**：慢歌/抒情歌可能没有明显鼓点，但过零率低、频谱重心低、频谱平坦度低——这是乐器与混音的特征。普通说话有较多清辅音和较高共振峰，过零率、频谱重心和平坦度都会更高，因此不会走这条通道。靠音色认出的音乐速度不可信时，BPM 会退回 0，前端按 96 的备用拍摇摆，而不是硬跟一个错误速度。

进入音乐状态需要得分 ≥ 0.32 并连续保持 1 秒；退出要 ≤ 0.20 并持续 1 秒，避免在边界抖。门限按真实 WASAPI 回环录音标定过：真实音乐的前奏/弱拍段常只有 0.25–0.4 的节奏证据，而普通语音通常低于 0.2；只按合成音轨会把门限定得过高，导致真实音乐完全进不来。`qiling-music-sense` 事件新增 `music` 字段，前端只有 `music === true` 时才进入舒缓/轻快/激烈；人声、噪声、音效仍会更新能量，但不跳舞。器灵自己播报时，前端还会在 `speaking` 期间强制不显示音乐状态，作为第二道保险。设定页的监听状态会显示最近 2 秒内听到的是“正在跟随音乐 · BPM”“听到声音，但不是音乐”还是“等待音乐”。

### 2. BPM 为什么原来不准，现在怎么改

旧实现只看低频起音的间隔中位数，并限制 70–160 BPM，带来三个问题：

- **60 BPM 直接落在 70 下限之外**，被当成“估不出速度”（这就是“半拍的识别不出来”）。
- 只抓低频，反拍踩镲/军鼓抓不到，容易把 120 听成 60，或把 90 的八分音符听成 180。
- 没有半拍/双拍候选，也没有置信度。

现在的做法：

- OSE 用全带宽，反拍、踩镲、军鼓都会进入起音包络。
- 在 6 秒窗口上做自相关（40–200 BPM），对峰值候选做梳状评分、速度先验（中心约 118 BPM）和节拍网格评分；窗口至少 2.5 秒后才开始估速。
- 候选包含 ×0.5 / ×1 / ×2 三种半拍/双拍关系；节拍网格的 occupancy 能区分“真正的 60 BPM”和“120 BPM 漏拍”。
- 沿用原型 `recommendTempoMode` 的取向：≥140 BPM 时，如果半拍候选（65–105）确实每拍都有稳定起音，就按半拍驱动动画；慢速时只有另半拍真的每一拍都有起音才加倍，避免把真正的 60 BPM 翻成 120。
- 速度更新每 0.5 秒一次；与上一拍相差超过 8% 时，要连续两次估计一致才切换，避免半拍/双拍来回跳。
- `qiling-music-sense` 新增 `bpmConfidence`；`qiling-music-beat` 只在判定为音乐且落在估计的拍点上时发出，不再“每个起音都算一拍”。

### 3. 验证

- Rust 单测：`cargo test --manifest-path src-tauri/Cargo.toml music`
  - 60 BPM 半拍（旧下限之外）能识别；
  - 120 BPM + 反拍踩镲不翻倍；
  - 90 BPM + 八分音符踩镲按半拍回到 90；
  - 合成语音、白噪声判为非音乐，且不产生鼓点；
  - 仓库自带 120 BPM 音频仍判为音乐、BPM 接近 120。
- 另外用 Windows SAPI 合成了中/英文人声做本地对照（16 秒连续说话），判定均为非音乐（未把音频提交进仓库）。
- 还用 WASAPI 回环录了真实系统输出做标定：音乐（SoundHelix）约 3–4 秒进入音乐状态；SAPI 中文人声录成回环后始终低于 0.2 分、不进入音乐状态。这组实测推动了门限从 0.55 下调到 0.32，并加了 1 秒进入驻留。
- 针对“抒情慢歌”又补了一组实测：用系统回环录了 30 秒 YouTube 慢歌（Ann 白安《是什麼讓我遇見這樣的你》）。它的节奏通道只有 0.0–0.28，低于旧门限；音色通道是 0.51–1.0。加入音色通道后 3 秒内进入音乐状态；因为鼓点证据不足，BPM 退回 0（前端按 96 备用拍），不会硬跟一个 150 BPM 的错误速度。

### 4. 局限与下一步

- 这是规则法，不是训练好的音乐分类模型。强节奏的语音、说唱、游戏音乐/音效、纯环境音仍可能误判。
- 半拍/双拍本身是节奏周期检测的固有歧义，运行时按“动画更自然”的取向取舍；以后如果要在设置页显示“检测主拍 / 半拍 / 双拍”，可以把这个选择暴露给用户。
- 如果以后要高准确率地排除语音，可以在这套特征后面接一个轻量 ONNX 分类器（输入用现成的 Mel/Chroma/OSE），采集和特征层不用重写。
- libsonare 仍然适合浏览器原型的整曲分析；桌面端已有 Rust 采集与特征，暂不引入 C++/WASM 依赖。它本身也不包含音乐/语音分类器，替换它并不能直接解决“语音被当成音乐”的问题。
